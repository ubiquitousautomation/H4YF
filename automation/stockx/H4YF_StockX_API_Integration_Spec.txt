2. THE THREE APIs (what each does for us)
════════════════════════════════════════════════


A. CATALOG API  → IMAGES + market data  [our image source #2]
   - Search products by style code / SKU / name (e.g. CT8527-400)
   - Returns product metadata + official StockX product images (clean studio shots)
   - Also returns market data (lowest ask, highest bid, last sale) — useful for pricing
   - USE: match catalog style codes -> StockX product -> pull image URL ->
          push to WooCommerce for items NOT covered by eBay API


B. LISTING API  → inventory management (asks)
   - A "listing" wraps what sellers call an "ask"
   - Create / update / delete asks programmatically
   - Asynchronous: write request validated synchronously, returns an operation id;
     StockX processes the ask on your behalf
   - USE: list website/eBay inventory to StockX automatically; adjust asks by market data;
          delist when sold elsewhere (prevents double-selling)


C. ORDER API  → sales
   - Retrieve active + historical sales
   - USE: pull StockX sales into File 2 (Sales & Platform Analytics) automatically;
          trigger website stock decrement when a pair sells on StockX

3. PROGRAMMATIC PLATFORM MANAGEMENT — TARGET ARCHITECTURE
════════════════════════════════════════════════


Unified inventory loop (Master Catalog = source of truth):


  Master Catalog (Sheet)
      |
      +--> WooCommerce (WC REST API)      [live]
      +--> eBay (Browse + Sell APIs)      [images now, sync next]
      +--> StockX (Catalog/Listing/Order) [images source #2, sync next]
      |
   Sync engine (Apps Script, runs every 2 hrs):
      - New catalog item -> create WC product + eBay listing + StockX ask
      - Sale on ANY channel -> decrement/delist on the other two (no double-sell)
      - Price change in catalog -> push to all three
      - Pull orders from eBay + StockX -> File 2 analytics


  This replaces / augments List Perfectly ($29/mo) for the eBay+StockX legs with
  direct API control. Keep List Perfectly only if Grailed/Mercari legs are still wanted.

4. PLANNED SCRIPT: h4yf_stockx_image_fetcher.gs (build after approval)
════════════════════════════════════════════════


Mirrors h4yf_ebay_image_fetcher.gs:
  CONFIG: STOCKX_API_KEY, STOCKX_CLIENT_ID, STOCKX_CLIENT_SECRET
  - _stockxToken_()      : OAuth client-credentials / refresh flow
  - _searchByStyle_(code): Catalog API search by style code -> product id + image
  - reads remaining IMAGELESS WC products (those eBay couldn't fill)
  - matches by Style Code (catalog has style codes: CT8527-400, FV5029-006, etc.)
  - previewStockxMatch() : dry-run, logs style-code -> StockX product -> image
  - executeStockxImagePush(): PUT images to WC for matched products
  - Output: final gap list = items needing in-house shoot


  NOTE: Style-code matching is MORE reliable than eBay title matching, because
  the catalog already stores exact style codes. This pass should be high-accuracy.
